# ADR 0001：产品与架构基线

- 状态：已接受
- 日期：2026-07-10
- 适用范围：第一阶段

## 背景

仓库同时存在业务前端、Sites 演示面和后端。若三者职责不清，会出现演示数据被当成业务结果、同一能力重复实现、视觉页面绕过校验直接触发规划等问题。

## 决策

1. `frontend/` 是唯一业务主前端。项目创建、数据导入、规则维护、校验、规划、风险复核、重规划、方案对比、报告导出和版本审计均从此入口完成。
2. `backend/` 是唯一业务能力与数据事实来源。任务数据、频谱规则、规划运行、风险结果、报告和审计记录以其 API 与持久化结果为准。
3. `battlefield-spectrum-site/` 是视觉原型和 Sites 演示面。其内置场景、指标和交互仅用于展示，不是业务数据，不得被引用为规划、验收或审计证据。
4. 演示面不得复制业务写操作，不得形成独立业务状态；需要产品化的交互必须回到 `frontend/`，并通过现有后端 API 落地。
5. 第一阶段采用“确定性工具决策、智能模型解释、人工最终采纳”的模式。LLM 只解释校验和规划结果，不生成或直接决定频率。

## 架构归属

| 层 | 责任 | 不承担 |
| --- | --- | --- |
| `frontend/` | 业务流程、人工确认、结果复核、导出与留痕入口 | 自行计算权威规划结果 |
| `backend/` | 输入校验、确定性规划、干扰评估、重规划、版本审计、报告导出 | 替代有权人员作最终业务决定 |
| `battlefield-spectrum-site/` | 视觉语言验证、静态/模拟交互、Sites 展示 | 真实数据录入、业务执行、审批、验收 |
| 外部 LLM（可选） | 对脱敏摘要做辅助解释 | 频率分配、规则变更、方案批准 |

## 决策权

- 任务负责人决定任务目标、优先级和可接受的保障降级。
- 频谱筹划员维护输入与规则，发起校验、规划、试算和重规划预览。
- 安全/合规复核员对禁用、保护、固定占用规则及高风险项拥有否决权。
- 授权指挥/业务负责人拥有方案最终采纳和对外发布权。
- 系统的“推荐”“综合分”和智能解释均为证据，不自动取得批准权。

当前版本没有认证、授权和角色隔离；上述权责是必须执行的流程控制，不得宣称已由系统强制执行。

## 安全基线

- 仅允许在本地受控环境处理演示、仿真或经批准的脱敏数据；不得接入实装控制链路或直接下发频率。
- 默认关闭外部 LLM。启用前必须确认接口、模型和传输策略获批，且只发送人工复核后的脱敏摘要。
- 重规划必须先预览变更，再由有权人员确认执行；预览可留审计记录，但不得改写已采纳方案。
- 报告和 Excel 属于可外传数据载体，导出后仍按源数据级别管理。

## 后果与变更规则

- 两套前端不追求功能对等；业务能力只在 `frontend/` 验收。
- 第一阶段边界和不可破坏行为见 `docs/domain/phase-one-boundary.md`。
- 任何将演示面升级为业务入口、让模型直接决策、绕过校验/确认或改变权威数据源的变更，必须新增 ADR 并同步安全评审。
