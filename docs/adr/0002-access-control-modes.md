# ADR 0002：身份与权限运行模式

- 状态：提议
- 日期：2026-07-10
- 适用范围：第一阶段后续改造与生产化准备

## 背景

当前 API 只校验项目是否存在，没有身份、项目归属和角色授权；审计主体也主要是固定的 `user` 或 `system`。直接加入单一登录开关会产生两类问题：本地演示流程被破坏，或生产环境可以误用无认证模式。

## 提议

使用同一套授权内核，并提供两种身份模式：

1. `trusted_local`：生成固定本地身份，不显示登录界面，只接受回环地址访问，用于本机开发、测试和脱敏演示。
2. `oidc`：验证组织身份提供方签发的令牌，用于生产部署；除健康检查外，所有 API 必须认证。
3. 生产环境若配置为 `trusted_local`、缺少 OIDC 必要参数或未启用强制审批，应拒绝启动。
4. `battlefield-spectrum-site/` 继续作为展示面，不进入业务权限闭环，也不向业务后端转发其身份头。

## 最小项目角色

| 角色 | 权限边界 |
| --- | --- |
| `viewer` | 查看项目、方案、风险和审计，不写入。 |
| `planner` | 导入数据、维护普通规则、校验、规划、比较、预览并提交审批。 |
| `reviewer` | 复核保护/禁用/固定占用规则、高风险结果和外发边界，可否决。 |
| `approver` | 在复核通过后最终采纳、应用或发布方案。 |

项目所有者负责成员管理，但不自动获得越过业务审批的权限。普通采纳的提交者和批准者必须不同；高风险规则或对外发布还要求复核者与提交者、批准者分别独立。

## 分阶段实施

1. 增加统一请求上下文、`Principal`、权限目录和可信审计 actor；本地模式保持现有前端无登录运行。
2. 增加项目所有者与成员关系，项目列表按成员过滤，所有项目接口使用统一项目权限依赖。
3. 引入数据库迁移框架，将现有本地项目归属 `local-user`；生产数据不得自动猜测所有者。
4. 接入确定的 OIDC 提供方，并在生产环境强制验证 issuer、audience、签名和有效期。
5. 将规则变更、重规划应用、方案采纳和发布接入提交、复核、批准、应用状态机。

## 配置基线

```text
APP_ENV=local|test|production
AUTH_MODE=trusted_local|oidc
LOCAL_PRINCIPAL_SUB=local-user
LOCAL_ALLOWED_CLIENTS=127.0.0.1,::1
OIDC_ISSUER=
OIDC_AUDIENCE=
OIDC_JWKS_URL=
CORS_ALLOWED_ORIGINS=
APPROVAL_POLICY=compat|enforced
AUTO_MIGRATE_LOCAL=true
TRUSTED_PROXY_CIDRS=
```

## 下一安全实施切片

在不改变当前业务流程的前提下，可以先实现：配置与生产启动保护、本地合成身份、回环限制、请求编号、权限依赖骨架、集中审计上下文、迁移框架和负向配置测试。

以下事项必须在实施生产登录前确定：OIDC 提供方与 claims、Bearer Token 或安全 Cookie/BFF、反向代理和 TLS 拓扑、历史生产项目所有者映射、二人或三人审批规则、生产数据库类型及审计保留期限。
